# Phase 12 — inspection of the existing training infrastructure

Read before any change. File/line references are to the repository at commit `79a216d`.

| # | Item | Where | What it does today |
|---|---|---|---|
| 1 | Training entry point | `scripts/run_experiment.py` (`main`, lines 198–423) → `src/finetune.py::run_schedule` → `src/train.py::fit` | One JSON config → staged fine-tuning on the **old** frozen manifest (`data/split_manifest.csv`, `split=train`/`val`), writes `results/experiments/<ID>/`. Also `python -m src.train` / `python -m src.finetune` CLIs. |
| 2 | Model construction | `src/model.py::build_classifier(num_classes, dropout, freeze_backbone, pretrained)` (lines 50–84) | torchvision `efficientnet_b0(IMAGENET1K_V1)` with `classifier = Sequential(Dropout, Linear(1280, K))`. `set_trainable_blocks`, `trainable_block_count`, `backbone_block_count` all index `model.features` (the 9 MBConv blocks). |
| 3 | Dataset construction | `src/manifest.py::build_split_dataset(split, transform, manifest_path)` → `ManifestDataset` (lines 216–284); `src/dataset.py::build_dataloader` (lines 138–168) | Rows of `data/split_manifest.csv` (`filepath,label,class_name,split`), digest-verified, decoded with `src/dataset.py::load_image` (Pillow → RGB; raises `ImageDecodeError`). Loader: seeded shuffle generator, `persistent_workers`, `pin_memory` on CUDA. Labels = canonical index from the manifest. |
| 4 | Preprocessing | `src/preprocessing.py::build_eval_transform(PreprocessConfig)` (lines 146–153); `CLAHE` class (79–118) | CLAHE (LAB-L, clip 2.0, 8×8; optional) → Resize(256, bicubic) → CenterCrop(224) → PILToTensor → float32 → ImageNet Normalize. The `PreprocessConfig` is stored in every checkpoint and rebuilt at inference. |
| 5 | Augmentation | `src/augmentation.py::build_train_transform(PreprocessConfig, AugmentConfig)` (47–71) | CLAHE → RandomResizedCrop(224, 0.8–1.0) → HFlip(0.5) → Rotation(±15°) → ColorJitter(0.2, 0.2[, sat]) → same tensor stage. Train only; `src/validation.py::assert_deterministic_loader` refuses random transforms on validation. |
| 6 | Loss | `src/train.py::train_one_epoch` line 260 | `F.cross_entropy(logits.float(), labels)`; no class weights, no label smoothing. |
| 7 | Optimizer | `src/train.py::build_optimizer` (174–198) | AdamW / Adam / SGD over two param groups — `head` (= `model.classifier` params) and `backbone` (= `model.features` params) with separate LRs (`TrainConfig.learning_rate`, `backbone_learning_rate`), `weight_decay`. |
| 8 | Scheduler | `src/train.py::build_scheduler` (201–209) | Optional `StepLR(step_size, gamma)` per stage; stepped once per epoch. No cosine, no warm-up. |
| 9 | Metrics | `src/metrics.py` (`confusion_matrix`, `metrics_from_confusion`, `compute_metrics`, `classification_report`); `src/validation.py::run_validation` | Pure-torch accuracy, macro P/R/F1, weighted F1, per-class P/R/F1/support, K×K confusion; validation in `eval()` + `inference_mode`, cross-entropy loss. Training-side only a running accuracy (`EpochStats.train_accuracy`), no train P/R/F1. |
| 10 | Checkpoints | `src/train.py::save_checkpoint` (310–356), `Checkpoint`/`load_checkpoint` (359–438) | Format v2: model + optimizer + scaler + scheduler state, epoch, history, `class_names`, `preprocess`, `train_config`, `best_epoch/metric`, `stage`, RNG states, loader generator state. `model_spec(model)` unpacks `dropout, head = model.classifier` and calls `trainable_block_count(model)` — both EfficientNet-specific. `Checkpoint.build_model()` calls `build_classifier`. Written as `checkpoints/<stage>/last.pt` + `best.pt`; runner copies the best to `best_model.pth`. |
| 11 | Device handling | `src/device.py::resolve_device(preferred)`, `torch_report` | Priority cuda → mps → cpu when unspecified; explicit name must be available or `RuntimeError`. AMP: float16 + GradScaler on CUDA, bfloat16 elsewhere (`autocast_dtype`, `build_scaler`). No "require CUDA" mode: an unspecified device silently picks CPU when no accelerator exists. |
| 12 | **Why the runner cannot take the hybrids directly** | `src/train.py` signatures are typed `EfficientNet` and rely on its structure: `set_train_mode` iterates `model.features` (line 165) to keep frozen blocks in `eval()`; `build_optimizer` splits `model.classifier` vs `model.features`; `model_spec` unpacks `model.classifier` as `(Dropout, Linear)` and calls `trainable_block_count` (block-suffix pattern over `model.features`); `Checkpoint.build_model` rebuilds via `build_classifier` only; `src/finetune.py::Stage.trainable_blocks`/`set_trainable_blocks` are block indices into `model.features`. The hybrids have no `.features` (they expose `.classifier` + `backbone_parameters()`), so every one of those calls fails. The runner also reads only the old manifest (`build_split_dataset`), not the fold/GAN manifests. | |
| 13 | **Minimum changes** | (a) one model factory `src/model_factory.py` that returns EfficientNet-B0 via the existing `build_classifier` or a hybrid via `build_hybrid`, plus generic head/backbone accessors; (b) a generic CV runner `src/cv_runner.py` + `scripts/run_cv_experiment.py` that reads the fold/GAN manifests, applies the hard leakage guards, trains with a model-agnostic loop, and writes `results/v2/experiments/<id>/`; it **reuses** `load_image`, `build_dataloader`, `build_eval_transform`, `build_train_transform`, `compute_metrics`/`confusion_matrix`/`classification_report`, `run_validation`, `resolve_device`/`torch_report`, `set_seed`, `is_improvement`, `autocast_dtype`, `build_scaler`, `_rng_state`/`_restore_rng_state`; (c) a config file family `configs/cv_v2/*.json`; (d) matrix generator/validator; (e) Colab notebook. | |
| 14 | **Untouched** | `scripts/run_experiment.py`, `src/train.py`, `src/finetune.py`, `src/model.py`, `src/manifest.py`, `src/preprocessing.py`, `src/augmentation.py`, `src/metrics.py`, `src/validation.py`, `src/dataset.py`, `src/device.py`, `src/hybrid_models.py`, `src/gan_augmentation.py`, all `results/experiments/*`, `data/split_manifest.csv`, `data/audit/split_v2/*`, `data/audit/cv_v2/*`. The historical baseline keeps running through its own runner unchanged; the new runner adds `--model efficientnet_b0` through the same factory so the baseline architecture is also trainable under the CV protocol. | |
